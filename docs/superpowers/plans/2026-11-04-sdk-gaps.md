# Community SDK 0.15 (showcase gaps) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the nine showcase workarounds into generic SDK options, release 0.15.0, and migrate Unchaind to it (streak data included) with verse sharing as the first attachment type.

**Architecture:** Each gap is one PR in `~/Developer/community-sdk`, branched from `main` after the previous one merged: pure helpers in `core`/`ui` (unit-tested with vitest), components wired to them, SQL migrations in the repo-root `supabase/migrations/<module>/` (copied into the CLI templates by `packages/cli/scripts/copy-templates.mjs`), verified on the scratch Supabase project and in the example app. Unchaind follows in two PRs in `~/Developer/unchaind`.

**Tech Stack:** TypeScript, React Native / Expo SDK 58, @tanstack/react-query, Supabase (Postgres, PostgREST), vitest, changesets, Argent for device QA.

**Spec:** `docs/superpowers/specs/2026-11-04-sdk-gaps-design.md`

## Global Constraints

- No new native dependency in `@rocapine/community-ui` or `-core`: Unchaind receives 0.15.0 by OTA on the 1.15.0 runtime.
- Breaking changes allowed (0.x); each one gets a "Migration" paragraph in its changeset. One release, 0.15.0, linked group (core, ui, CLI).
- Every new user-facing string is added to **all 13 locales** in `packages/ui/src/locales/` (`en, es-ES, es-419, fr, fr-vous, de, it, pl, pt-PT, pt-BR, ko, ro, uk`); `i18n.test.ts` checks key parity.
- Colours, spacing and type come from the theme; no literal sizes left in a file a task touches.
- Per PR: `npm run typecheck && npm test` and `npx prettier --check .` green at the repo root; one changeset (`npx changeset`); an Argent recording of the example app in the PR body when something is visible (global rule `~/.claude/rules/pr-video.md`).
- Scratch backend: Supabase `cozfrhmbjrvotpwjnqmu` (agents may change anything). Unchaind sandbox `vjcdpodsrpemanfvrshh` (agents may deploy). Unchaind prod `doiafuhoourjtqsmzook`: Guillaume only — hand him the exact commands.
- Security stance (spec): badge data and attachments are client-written, guarded only by size/shape checks.
- Git: branch per PR (`feat/<slug>`), conventional commits, PR body ends with the Claude Code line; never push to `main`.

## Review Focus

1. **A post or profile from a member who never synced badges** (`badges = '{}'`, old cache without `authorBadges`): renders with no badge and no crash. → Task 6.2 (`mapPostRow` test with no `author_badges` embed) and Task 6.4 (`badgesFor` with `undefined`).
2. **An old 1.15.0 bundle writing `streak_started_at` after the expand migration**: new clients see the same streak; a new client hiding `bestStreak` hides it for old clients too. → Task 6.1 SQL assertions both directions.
3. **A header zone listing `"inbox"` with the inbox module off, or a zone that ends up empty**: no gap, centre stays centred. → Task 4.1 `resolveHeaderZones` tests.
4. **A `composeRequest` with an attachment from a non-official member when `membersCanAttach` is false**: composer opens with the text, without the attachment, one `console.warn`. → Task 9.4 `allowedAttachment` test.
5. **A source locale with region and no base entry either** (`zh-Hant`): raw code, as before. → Task 2.1.
